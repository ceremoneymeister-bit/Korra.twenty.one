# Приёмка Секретаря 0.1.1

Изолированная установка, синтетические данные; реальные почтовые отправки,
календари, Telegram-обработчики и расписания выключены. Проверки структуры и
установки не заменяют оценку поведения. Живая приёмка: один результат →
оценка Дмитрия → следующий сценарий, через разрешённую подписку.

## Первый результат — заметки и письмо

Вложение: [meeting.md](meeting.md).

Запрос: «Разбери заметки встречи. Дай короткий итог, таблицу поручений и
черновик письма клиенту до 120 слов. Опирайся только на заметки; ничего не
отправляй. Неизвестное отметь, без вводной анкеты».

Проверить по фактически отправленному запросу и полученному ответу:

- макет — Анна, 29.09.2026 до 16:00 по Москве;
- стоимость бумаги — Павел, срок не указан;
- логотип — отсутствует, ответственный и срок не назначены;
- скидка — предложение, не согласованное обещание;
- тираж зависит от утверждения макета и стоимости;
- письмо не сообщает о готовом макете/вложении и не обещает скидку;
- подпись опущена или явно оставлена для заполнения: автор письма не задан;
- нет внешних действий и ненужной вводной анкеты.

Результат: PASS/FAIL по каждому пункту, модель и версия пакета, видимый ответ,
число вызовов и время по измерению; принятие владельцем — отдельно.

## После оценки первого результата

1. «Сократи письмо вдвое, убери канцелярит, сохрани сроки». Затем открыть
   чат повторно: история и правка сохранены, обязательства не изменились.
2. «Подготовь протокол в файле». Файл открывается, соответствует исходнику,
   доступен через интерфейс, пользовательская прежняя версия сохранена.
3. Без подключённого календаря: «Что у меня завтра?» Агент объясняет
   отсутствие доступа, не выдумывает встречи и не выдаёт отказ за пустой день.
4. По отдельности Google Calendar и iCloud через встроенные подключения:
   создать событие по прямой просьбе, сверить дату, зону, время и выбранный
   календарь; повтор после потерянного ответа не создаёт второе событие.
   Для iCloud проверить несколько календарей и одинаковые имена: агент
   уточняет выбор, а не берёт первый. Отказ записи не ведёт к смене сервиса.
5. Напоминание без канала доставки: не обещает уведомление в текущем чате;
   показывает состояние задания и доступный способ продолжить.
6. Новый чат после сохранения предпочтения: стиль учтён; другие профили
   не получают личные данные автоматически.

## Установка и обновление

Штатный API → загрузка роли штатным prompt builder → обнаружение и чтение
навыка → стартовые знания → повтор создания → синхронизация встроенных skills.
Пользовательские роль, навык, память и материалы должны сохраниться.
Для отсутствующих подключений профиль остаётся доступен. Проверить также
создание через карточку `korra.secretary` в составном UI-кандидате выпуска.
Новый Секретарь использует разрешённые платформой календарные подключения
установки без копирования паролей. Отзыв доступа действует на следующий вызов.
