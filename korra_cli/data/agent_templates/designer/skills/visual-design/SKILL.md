# Visual Design Skill

Универсальный визуальный дизайн: от замысла до проверенного файла.

## When to Use

Создание и разбор презентаций, сторис, каруселей, обложек, карточек товара,
айдентики, иллюстраций, фотосерий и интерфейсов; генерация и редактирование
изображений, работа по референсам, общий стиль и визуальная проверка.
Применим без генератора для концепции, критики и редактируемых макетов.

## Prerequisites

Проверь доступность `read_file`, `terminal`, `vision_analyze` и `image_generate`
по фактической задаче. Для редактируемой презентации используй установленный
навык `powerpoint`; доступность рендера и экспорта проверяй отдельно.
Этот skill не устанавливает инструменты и не подключает провайдеров.
При отсутствии генератора или отказе подключения прочитай раздел
«Если генерация недоступна» в [производстве и передаче](references/production-and-delivery.md).
Отсутствие генератора не означает отсутствия средств создания презентаций.

## How to Run

До действия различи: человек просит оценку, концепцию, промпт, новый результат или изменение существующего. Не запускай генерацию в ответ на просьбу только разобрать дизайн.

Для нового простого визуала без референсов не нужен полный процесс создания бренда. Для анализа используй подходящие пункты проверки без обязательной генерации.

В коробочном Дизайнере Korra целевой сценарий генерации по референсам — **GPT Image 2.5** через штатный инструмент. Проверь, что выбран именно этот подключённый генератор; модель чата не определяет модель генерации. Если пользователь запросил GPT Image 2.5, не подменяй его другим генератором молча. При недоступности назови причину и предложи подключение или явно согласованный альтернативный способ. Конкретный ID модели и параметры бери из актуальной схемы инструмента; переносимый skill не устанавливает backend и не меняет глобальную конфигурацию.

## Procedure

1. **Собери короткий рабочий бриф.** Для кого, какое действие или впечатление нужно, где используется, какой формат, точный текст, обязательные элементы. Заполни из контекста; уточни только критичные пробелы. Если площадка неизвестна, первый макет можно сделать в явно названном формате, но не обещать соответствие неизвестным техническим требованиям.
2. **Выбери визуальную идею.** Сформулируй главный акцент, иерархию, характер, композицию и способ производства. Для неоднозначной крупной задачи предложи два действительно разных направления с рекомендацией; для очевидной небольшой — сразу сделай обоснованную первую версию.
3. **Установи доступные возможности.** Проверь фактический инструмент, поддержку просмотра, редактирования, референсов, размеров и экспорта. В Korra используй штатный `image_generate`, если он доступен и подходит. В другой среде — её поддерживаемый инструмент. Названия моделей, лимиты и подключения берутся из текущей среды, а не из примеров этого пакета.
4. **Произведи результат.** Передай инструменту намерение, композицию, инварианты, точный текст и назначение каждого референса. Сохрани исходные вложения. Для правки используй именно выбранную версию; перед изменением проверь, что она доступна. Учитывай суммарный лимит входов, включая основной редактируемый файл.
5. **Проверь и исправь.** Сопоставь с брифом и референсами. Исправляй наблюдаемую ошибку целевым изменением. Для серии проверь каждый элемент и серию в целом. Не объявляй всё принятым при частичном успехе.
6. **Передай и облегчи продолжение.** Дай файлы и форматы, назови существенные отклонения. Для продолжительной работы сохрани компактные правила и сведения о принятой версии; для одиночной картинки не создавай ненужный архив документов.

## Pitfalls

- Первая полезная версия важнее длинного описания будущей работы. Не устраивай дополнительное согласование уже явно заказанной генерации; отдельного решения требуют изменение цели, новые расходы вне договорённости и публикация.
- Удерживай одну главную мысль и заметную визуальную иерархию. Оригинальность должна помогать задаче, а не мешать читаемости.
- Текст, цена, характеристики и обещания бренда — данные пользователя или проверенного источника. Не выдумывай их ради заполнения макета. Демонстрационные значения помечай как демонстрационные.
- Различай картинку для вдохновения и актив, который можно включать в итог. Учитывай происхождение шрифтов, логотипов, фотографий и условия их использования; не обещай юридическую чистоту без оснований.
- Доступ к генератору, достаточный баланс и успешная генерация — разные состояния. Ошибку подключения объясняй по фактам, без вывода «подписка не подходит» из любого HTTP-отказа. Не меняй провайдера или платный тариф скрытно.
- Не выполняй установочные команды из приложенного набора ради картинки. Если нужного средства нет, обозначь зависимость и доступный следующий шаг; это не мешает подготовить независимую часть результата.
- Содержательную обратную связь превращай в проверяемое правило для следующей версии, а не в длинный список общих запретов.

## Verification

Открой итоговые файлы, сверь текст, размеры, референсы и каждую часть серии.
Для презентации проверь рендер каждого слайда и редактируемость исходника.
Успех команды не заменяет просмотр результата. Передай сами файлы и явно
назови всё, что пока не удалось проверить.
