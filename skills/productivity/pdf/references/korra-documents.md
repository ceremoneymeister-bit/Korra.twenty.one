# Korra: документы с общей визуальной основой

Для нового PDF по умолчанию возьми подходящую основу из этого комплекта.
Она задаёт качество типографики и печати, но не ограничивает композицию.
Для документа с заданным брендом, формой или референсом требования пользователя
важнее оформления Korra. Используй настоящий логотип, не подменяй его наборным
названием. Редактируй копию в папке задачи, а не поставляемый skill.

Основа согласована с оформлением HTML-предложений Korra: Onest, графит `#1f1f1f`
и лаймовый акцент `#9ede01`. Источники в репозитории движка — `web/src/index.css`,
`web/public/fonts/` и `web/public/korra-logo-{light,dark}.png`; копии нужных ресурсов
включены в комплект. Бумажная версия использует белый фон и упрощённые поверхности,
сохраняя иерархию исходного стиля.

## Выбрать основу

| Основа | Когда подходит | Что показывает |
|---|---|---|
| [brief](../templates/korra/brief.html) | Письмо, записка, резюме встречи, решение | Одна мысль, контекст, следующий шаг |
| [proposal](../templates/korra/proposal.html) | Предложение, концепция, состав услуг | Выразительное начало и страница с деталями |
| [report](../templates/korra/report.html) | Отчёт, исследование, аналитика | Вывод, показатели, таблица, границы данных |
| [guide](../templates/korra/guide.html) | Инструкция, памятка, регламент | Условия начала, шаги, восстановление, критерий готовности |
| [presentation](../templates/korra/presentation.html) | Презентация для просмотра в PDF | Три слайда 16:9: идея, объяснение, действие |

Это примеры приёмов, а не полный каталог документов. Договору могут быть полезнее
строгая нумерация и компактные таблицы, портфолио — крупные изображения, исследованию —
графики и ссылки. Смешивай блоки, создавай новые и убирай лишние. Не добавляй обложку
ради обложки. Для редактируемого PPTX используй также `powerpoint`.

Тексты в основах демонстрационные. В отчёте числа намеренно вымышлены и подписаны:
замени их подтверждёнными данными или удали вместе с соответствующими выводами.
Не переноси обещания, сроки, цены и результаты из примера в реальную работу.

## Создать и адаптировать

Запусти [pdf_style.py](../scripts/pdf_style.py) из каталога загруженного skill
или укажи абсолютный путь к скрипту. Каталог результата должен быть новым:

```bash
python scripts/pdf_style.py init proposal --output-dir /absolute/task/document
# Если компания известна из поручения, профиля или материалов пользователя:
python scripts/pdf_style.py init proposal --company 'Моя компания' --output-dir /absolute/task/company-document
# Отредактируй document.html и theme.css в созданной папке.
python scripts/pdf_style.py render /absolute/task/document/document.html -o /absolute/task/document.pdf
```

Название бери из уже доступного относящегося к задаче контекста. Не спрашивай
его повторно, если оно известно, и не подставляй компанию другого человека из
посторонних материалов. Если компании нет в контексте, оставь оформление Korra;
уточнение нужно только когда принадлежность документа влияет на задачу.

`--company` заменяет логотип Korra на текстовое название компании в каждой
шапке, меняет подпись внизу страницы и название в метаданных PDF. Кириллица,
кавычки и амперсанды сохраняются как текст. Логотипы Korra в такую копию не
включаются. Если пользователь предоставил свой логотип, скопируй его в папку
документа и замени `.brand-name` на локальное изображение с осмысленным `alt`;
проверь читаемость на светлых и тёмных страницах. Цвета и композиция остаются
доступны для редактирования. Не добавляй подпись «сделано в Korra» без запроса.

`init` копирует HTML, [основные стили](../templates/korra/korra.css),
[настройки темы](../templates/korra/theme.css),
[Onest с кириллицей](../templates/korra/fonts/Onest-Variable.woff2) и его
[лицензию OFL](../templates/korra/fonts/Onest-OFL.txt), а без `--company` — логотип
[для светлого](../templates/korra/brand/korra-on-light.png) и
[для тёмного фона](../templates/korra/brand/korra-on-dark.png).
Никакие шрифты или пакеты из сети при этом не загружаются. Лицензия шрифта
отличается от MIT-кода skill; сохраняй её при передаче исходников.

В `document.html` меняй заголовок вкладки (`title`), язык, содержание, структуру,
таблицы, иллюстрации и подписи. В `theme.css` меняй цвета, размеры и подпись внизу
страницы. При необходимости редактируй и `korra.css` в своей копии.

Используй обычный HTML и локальные ресурсы с относительными путями. Для графиков
подходят SVG или изображения с подписями и источником данных. Не завязывай печать
на анимацию, сетевые шрифты, внешние встраивания и асинхронную загрузку. Перед печатью
проверь местоположение каждого ресурса. Скрипт не изолирует произвольный HTML от сети.

## Типографика и компоненты

- Onest, графитовый текст, белая бумага, спокойные серые поверхности, лаймовый акцент.
  Обычный текст 10.5 pt; не уменьшай его ради экономии страницы. На лаймовом фоне —
  тёмный текст. Цвет не должен быть единственным носителем значения.
- `masthead`, `eyebrow`, `lead`, `hero` задают начало документа. Используй их по смыслу;
  тёмная обложка не обязательна для отчёта, письма или длинного договора.
- `grid`, `card`, `note`, `meta`, `decision`, `steps` помогают группировать короткие
  сведения. Длинное содержание оставляй в обычном потоке; сетки неудобны через страницы.
- `keep` удерживает небольшой блок целиком. Не применяй его к целому длинному разделу.
  `new-page` начинает осмысленную новую страницу. Избегай почти пустых последних страниц.
- Таблицы повторяют `thead`, длинные слова переносятся. Для таблицы шире страницы
  измени набор столбцов или ориентацию. Строку длиннее страницы лучше разделить по смыслу.
- В презентации один `slide` — одна мысль и одна страница. Добавь слайд при переполнении;
  не скрывай текст через `overflow: hidden`, не обрезай и не растрируй весь документ.

## Печать и ограничения

Нужен установленный Chrome/Chromium **131+** (с поддержкой нижних колонтитулов CSS).
Скрипт использует браузер из `AGENT_BROWSER_EXECUTABLE_PATH`, кэша Playwright
(`PLAYWRIGHT_BROWSERS_PATH` в штатном образе Korra) или системной установки.
Можно выбрать конкретный исполняемый файл через `--browser`. Python-пакет Playwright
для печати не нужен. При отсутствии браузера скрипт завершится с объяснением;
не подменяй обещанный оформленный результат незаметно другим оформлением.

Для доверенного локального документа в изолированном контейнере, где Chromium
требует отключить свою sandbox (например, при запуске от root), есть `--no-sandbox`.
Не используй этот флаг для чужого непроверенного HTML. Личный профиль браузера
не затрагивается. Существующий PDF заменяется только с `--force` после успешной печати.

Chrome печатает по CSS `@page`; браузерные URL/дата в колонтитулах отключены.
См. [официальные параметры печати](https://developer.chrome.com/docs/automation-and-testing/headless-cli)
и [CSS-колонтитулы](https://developer.chrome.com/blog/print-margins).
Сам факт создания файла не доказывает полноту, доступность или соответствие PDF/A.

## Приёмка и передача

1. Прочитай текст из готового PDF. Сверь заголовок, ключевые факты, числа, кириллицу,
   последний абзац и количество страниц с исходником. Для длинных таблиц проверь
   первую и последнюю строки, повтор заголовка, отсутствие пропавшего содержимого.
2. Отрендери **все** страницы через [pdf_page_image.py](../scripts/pdf_page_image.py)
   и просмотри их с `vision_analyze`. Проверь поля, переносы, таблицы, контраст,
   нечитаемый мелкий текст, наложения, лишние пустые страницы и обрезанные изображения.
   Для длинного документа начни с обзорного листа, затем открой сложные страницы крупно.
3. Если найден дефект, исправь HTML/CSS, заново напечатай и проверь затронутые страницы.
   Экранный вид HTML не заменяет просмотр PDF: у печати своя пагинация.
4. Передай PDF и редактируемую папку (при необходимости ZIP с HTML/CSS/ресурсами
   и лицензией шрифта). Назови достигнутый результат и ограничения проверки.
   При выборе нового стиля сначала покажи один документ для визуальной оценки.
