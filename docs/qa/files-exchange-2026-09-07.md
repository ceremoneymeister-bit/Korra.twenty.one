# Обмен файлами в панели — 07.09.2026

Реализована выдача документов через штатный `MEDIA:`, скачиваемые карточки в истории, общая рабочая папка для загрузок и результатов, прикрепление существующего файла из «Файлов». Проверено на отдельном `astra-files`: панель **9145**, API **8675**.

**Ограничение проверки модели:** настоящий запрос к `dario` вернул HTTP 401: OAuth access token has expired. `/status` при этом сообщал healthy/authenticated, но срок токена истёк. Независимого рабочего Anthropic API-ключа в тестовой копии нет. Поэтому подтвердить, что настоящая модель сама следует новой подсказке, не удалось. Ниже браузерные сценарии выполнены с локальным управляемым провайдером на 8685, согласно разрешённому в `common.md` fallback. Шлюз, инструменты, файловая система, загрузка, авторизация, SSE и SQLite-история при этом настоящие. Это проверка интеграции, а не доказательство поведения живой модели.

## Что было сломано

- `agent/prompt_builder.py`, подсказка `dashboard`: прямо предписывала отдавать документы простым текстом, без `MEDIA:`. Это воспроизводило ограничение API, хотя панель умеет скачивать файлы.
- `gateway/platforms/api_server.py::_resolve_media_to_data_urls`: заменял только изображения до 5 МБ на base64. Для документов не было доставки, а картинки обходили проверку рабочей папки раздела «Файлы».
- `web/src/components/Markdown.tsx`: ссылки `sandbox:`, `file://` и локальные пути превращались в обычный текст. Именно такой ответ из брифа теперь становится карточкой.
- `_chat_client_root` сохранял загрузки в `client/inbox`, тогда как fleet без принудительного корня показывал только `workspace`. При контейнерном `FILES_ROOT=/opt/data` обратная проблема: принудительный корень открывал всё дерево данных вместо рабочей папки.
- Карточки пользовательских вложений показывали только название и размер. Отправить уже существующий файл из «Файлов» было нельзя.
- Прямая fleet-панель не передавала авторизацию при нативном скачивании: `artifactUrl` намеренно не раскрывает токен в URL. Браузер отменял загрузку. Это воспроизведено в Playwright и исправлено без ослабления авторизации.

## Поведение после изменения

**Агент → человек.** Принимаются `MEDIA:/абсолютный/путь`, `MEDIA:"/путь с пробелами"`, Markdown-ссылки с абсолютным локальным путём, `sandbox:` и `file:///`, а также отдельная строка с абсолютным именем файла. URL-кодированные имена поддержаны. Несколько ссылок на один путь дают одну карточку. Обычные внешние ссылки и блоки кода сохраняют прежнее поведение; произвольные относительные пути в прозе автоматически не превращаются в файлы.

Карточка запрашивает имя/размер через `GET /api/files/attachment`; скачивание идёт через существующий `/api/files/download` с дополнительной проверкой `chat=1`. Обе операции применяют `_resolve_managed_path` и запрет служебных файлов. Проверены выход за корень, `..`, симлинки, `.env`, закрытые данные профиля, отсутствие авторизации и сетевой authority у `file://`. Запрет нельзя обойти форматом ссылки. Не найденный, перемещённый, недоступный или слишком большой файл получает понятное сообщение вместо рабочей кнопки.

В прямой панели бинарный запрос использует существующий `authedFetch` с заголовком авторизации, после чего браузер скачивает Blob. Токен панели не появляется в URL. При cookie-авторизации без bootstrap-токена сохраняется нативное скачивание. Для прямого режима Blob ограничен серверным пределом 100 МБ; отдельная система токенов или публичная раздача файлов не добавлялась.

Изображения получают превью через тот же защищённый файловый маршрут. Превью ограничено 25 МБ; сам файл можно скачать до 100 МБ. Для обычных сторонних клиентов API сохранён прежний механизм инлайна картинок; ответ панели сохраняет исходный `MEDIA:` без base64.

**Человек → агент.** Загрузки идут в `workspace/client/inbox/<дата>/`. Файл записывается по частям по 1 МБ во временный соседний файл, затем публикуется атомарно. Пустой/прерванный/превышающий лимит файл не оставляет частичный документ. Новые `.meta.json` рядом с каждым вложением больше не создаются: descriptor и SHA-256 возвращаются клиенту, история уже хранит нужный путь и подпись. Уникальное имя предотвращает перезапись другого документа.

Поддержаны несколько файлов, drag-and-drop и вставка из буфера. Повторный выбор/перетаскивание одного файла не запускает ещё одну загрузку, в том числе при повторном выполнении React updater в StrictMode. До пяти вложений в сообщении; загрузка из чата — до 50 МБ на файл. Ограничения проверяются и в интерфейсе, и на сервере.

**«Файлы» ↔ чат.** У карточки есть «Показать в „Файлах“». В списке файлов появилась кнопка «Отправить в чат»; рядом со скрепкой — выбор существующего файла рабочей папки. Оба пути прикрепляют существующий descriptor, не копируют и не загружают документ ещё раз. Отправку сообщения подтверждает сам пользователь. Диплинк принимает только активная вкладка агента: скрытые, постоянно смонтированные вкладки его не потребляют.

**История.** Ссылки агента и блок `[вложения]` остаются штатным текстом разговора. Карточки восстанавливаются из истории после reload; новые поля схемы сообщений или отдельная база вложений не понадобились. Подсказка объясняет `MEDIA:`, рабочую папку и новое имя для новой версии. Сохранённые системные промпты существующих разговоров не переписываются: новый текст подсказки действует в новых разговорах, а совместимость со старыми `sandbox:`-ответами обеспечена рендерером.

## Профили и рабочая папка

У профиля остаётся свой каталог данных: `/opt/data/profiles/<имя>`. `_profile_runtime_scope` из `gateway/run.py` изолирует конфигурацию, память, навыки и секреты через контекст профиля. Это не означает отдельный cwd терминала: его базовое значение приходит из `terminal.cwd`, мостится в `TERMINAL_CWD` при старте шлюза и читается `tools/terminal_tool.py`.

В проверенной конфигурации локального мультиплекса cwd и у основного агента, и у `lawyer` — `/opt/data/workspace`. Это подтверждено настоящим вызовом terminal профиля: `cwd_is_workspace: true` в receipt. Поэтому fleet использует **общую workspace контура**, вычисленную через `get_default_hermes_root()`, даже при выбранном профиле и старом контейнерном `FILES_ROOT=/opt/data`. Приватное дерево `profiles` в «Файлы» не попадает. Отдельные удалённые терминальные backend с другой файловой системой здесь не проверялись.

## Что намеренно не сделано

- Не добавлен новый инструмент модели, отдельный протокол доставки или новая схема хранения сообщений: штатного MEDIA и существующего Files API достаточно.
- Не открыты все каталоги профилей ради скачивания одного документа. Старые загрузки вне workspace не перемещались автоматически и не объявлялись публичными: это могло бы раскрыть служебные данные и сломать сохранённые пути. Их исходные файлы и история остаются на месте; для выдачи нужно сохранить нужный документ в workspace. Такое перемещение нельзя считать проверенной автоматической миграцией этой правки.
- Не введено автоматическое удаление «неиспользуемых» загрузок: файл может понадобиться в другом разговоре. Удаление остаётся осознанным действием в «Файлах».
- Не создаются скрытые копии каждой версии документа. Перезапись или удаление файла самим пользователем/агентом меняет доступность старой ссылки; подсказка требует отдельного имени для новой версии, карточка объясняет недоступность.
- Живые сообщения в Telegram не отправлялись: тестовая копия не содержит TELEGRAM-настроек, паритет проверен на штатном extractor.
- Не обновлялись рабочие контуры, не выполнялся вход на сервер Ларисы, не собирался образ и не делался push. `astra-files` оставлен как тестовый стенд с локальным управляемым провайдером; его нельзя принимать за подключённую рабочую модель.
