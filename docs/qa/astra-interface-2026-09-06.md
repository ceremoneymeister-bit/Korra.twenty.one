6. **Ключи оставались каталогом для оператора.** На эталоне сразу показывались десятки провайдеров, пустых переменных и команды терминала. Сохранился английский абзац про шлюз. В настройках поиск не учитывал русские подписи, которые человек видел на экране.

Как решена навигация:

- Прослежена настоящая цепочка: nginx передаёт `/c/…` сервису кабинета; `/opt/korra-cabinet/app/proxy.py` снимает префикс и добавляет `X-Forwarded-Prefix`; `mount_spa` в `korra_cli/web_server.py` внедряет `window.__HERMES_BASE_PATH__` в HTML. `web/src/lib/api.ts` читает его, `web/src/main.tsx` задаёт `basename` единственному `BrowserRouter`. Отдельной пользовательской переменной окружения для префикса не нужно.
- SDK расширен полем `router`: это **те же** `Link`, `NavLink`, `useNavigate`, `useLocation`, `useHref`, `useSearchParams` из роутера панели. Новой системы маршрутизации или вычисления клиента по адресу нет. Плагин передаёт путь раздела, а префикс добавляет роутер.
- Манифесты и `/dashboard-plugins` продолжают использовать существующую загрузку. Встроенные ссылки моделей и аналитики на настройки тоже переведены на `Link`. Для API, файлов и WebSocket остаются штатные функции SDK.
- Плагин канбана заполняет уже существующий слот `cron:top`: из «Задач» можно перейти к разовому поручению. Кэш манифестов и запомненная доска разделены по базовому пути кабинета.
- Контракт и пример использования: [docs/dashboard-plugin-navigation.md](/opt/korra-21/docs/dashboard-plugin-navigation.md). Старые поля SDK не удалялись; обновлённые плагины требуют обновлённого основного фронта.

Что изменилось для пользователя:

- Адрес канбана хранит `board`, `task` и представление `view`. Ссылку на поручение можно скопировать; она открывается после перезагрузки и в другой вкладке. Возврат браузером сохраняет кабинет. Несуществующая доска не подменяется молча другой.
- В «Пользе» появились ссылки на конкретные доски, требующие внимания; «Посмотреть результаты» открывает результаты. Работающими считаются только включённые расписания с успешным последним запуском. Приостановленные учитываются отдельно. «Освоено» заменено нейтральным «Есть данные».
- На канбане есть быстрые представления «Все поручения», «Нужно ваше внимание», «Результаты». После создания открывается сохранённая карточка. В готовой работе первым виден результат, задание можно раскрыть. Полный результат сохраняется при приёмке и в архиве.
- Открытая карточка обновляется автоматически, не стирая набранный комментарий. До появления результата ручное действие называется «Завершить поручение», на проверке — «Принять результат». Приоритет выбирается словами; прежние числовые значения сохраняются.
- Исходные файлы прикрепляются при создании. Сначала сохраняется карточка без исполнителя, затем загружаются файлы, затем назначается агент. При ошибке загрузки нет преждевременного запуска; повтор не создаёт вторую карточку и не дублирует уже успешно загруженный файл. При неопределённом исходе передачи повтор сначала проверяет сервер. Отказ сервиса ответов в истории больше не предлагает бессмысленно переписывать само задание.
- В ключах первыми видны настроенные сервисы, в том числе расширенные ключи реально подключённого провайдера. Остальные доступны через «Подключить сервис» и поиск по названию или ключу. Способы входа раскрываются отдельно, команды находятся под «Подключение через терминал» и копируются как `korra …`. Убраны английское пояснение и оставшиеся рамки.
- Общие параметры получили русские подписи; поиск учитывает их, подписи расширений и технические ключи. В настройках есть переходы к карточкам агентов, моделям и каналам. Формат и значения конфигурации не мигрировались.
