При восстановлении разговора `conversation_loop` берёт сохранённый системный
промпт из БД. Новая подсказка не вставляется задним числом в прошлый контекст,
не добавляет синтетических сообщений и не меняется на каждом токене.
Существующий механизм `platform_hints` поддерживает отдельное переопределение
`dashboard`; для обычного API сохраняется ключ `api_server`.

У Telegram собственный адаптер `plugins/platforms/telegram/adapter.py`.
Обычный Markdown переводится в MarkdownV2: спецсимволы экранируются, код
защищается от преобразований, заголовки становятся выделением, таблицы —
последовательностью подписанных строк. Обычный `sendMessage` ограничен 4096
символами; адаптер учитывает UTF-16 и делит длинный ответ, восстанавливая ограды
кода. Ошибка разбора действительно отвергает попытку отправки, но уже есть
повтор с очищенным текстом и `parse_mode=None`. Отдельный богатый путь существует
и включается настройкой; его не включал. Ограничения сверены с
[Telegram Bot API](https://core.telegram.org/bots/api#sendmessage) и
[правилами разметки](https://core.telegram.org/bots/api#formatting-options).

Итог для совместимости: панель и Telegram используют общее ядро, но теперь
имеют разные подсказки оформления и прежние отдельные рендереры. Даже источник
`dashboard` при платформе `telegram` не переключает Telegram на веб-подсказку;
это проверено тестом.

## Что изменилось для читателя

Ответ получил отдельную спокойную поверхность с внутренними полями. Служебный
ход расположен снаружи, над ней. Основной текст — Onest 17 px / 30,6 px вместо
16 px / 28 px; на телефоне — 16 px. Максимальная ширина ответа — 780 px с полями
32 px на большом экране и 18 px на телефоне. Увеличены промежутки между абзацами,
пунктами и разделами; заголовок второго уровня — 1,4 em. Цвета и глубина взяты
из канона, рамок и обводок не добавлено.

У кода появилась постоянная верхняя панель: язык и «Скопировать код».
Копирование сохраняет отступы и переносы, не захватывает язык, ограды и курсор
потока. Кнопка «Скопировать ответ» видна под готовым ответом, в том числе на
телефоне. Отказ буфера больше не выглядит как успех: доступен повтор.

Таблицы получили более свободные ячейки и сохранили выравнивание чисел.
Если столбцы не помещаются, появляется «Таблицу можно прокручивать вбок»;
при достаточной ширине этой подсказки нет. Прокручивается таблица, не страница.
Цитаты, ссылки и вложенные списки сохраняют отдельное оформление. Моноширинный
шрифт остаётся у кода и команд.

После завершения инструментов, когда приходит текст, след сворачивается с
подписью «Пишу ответ…». Новый работающий инструмент снова раскрывает его.
Человек может раскрыть подробности сам; число ошибок видно и во время потока.
Пустая карточка ответа при одной лишь работе инструмента не рисуется.

Автопрокрутка следует за ответом, пока человек находится внизу. Прокрутка вверх
останавливает следование. Кнопка возвращает к последнему ответу; если агент
ждёт одобрения, она сообщает об этом. Новый собственный вопрос возобновляет
следование. Загрузка вложений и изменение высоты следа учитываются через
`ResizeObserver`.

Ориентир Claude.ai / ChatGPT применён как набор привычных решений: документная
иерархия, пространство между разделами, отдельный код с копированием и контроль
прокрутки. Доступные публичные страницы без входа не дают сравнить реальные
приватные диалоги этих продуктов; точное совпадение с их CSS не заявляется.
Выбор длины строки и интервалов также сверялся с
[W3C Visual Presentation](https://www.w3.org/WAI/WCAG22/Understanding/visual-presentation.html).

(`/tmp/astra-ui-proxy.eczap736/nginx.conf`). Чужой процесс не остановлен.
Рабочая проверка выполнена на **127.0.0.1:9145**, API — **8671**.
Промежуточная попытка 127.0.0.2:9141 была отклонена штатной проверкой
аутентификации панели; её не обходил.

Данные кандидата созданы отдельно в `/tmp/astra/chat2/data`:
конфиг скопирован только чтением, секции `telegram` удалены рекурсивно,
в `.env` взята только строка `DARIO_API_KEY`, ключ API создан новый.
В контейнере проверено отсутствие `TELEGRAM_*` в окружении и `.env`, а также
`telegram` в конфиге. Живой отправки Telegram не было.

В конфиге владельца к моменту копирования основной моделью уже был Codex,
а его данные авторизации копировать задание не разрешало. Запрос с этим
неполным набором вернул `No Codex credentials stored`. Для предусмотренной
заданием проверки Dario только в копии выбран уже существующий провайдер
`custom:dario` и его модель `claude-opus-4-8`. До изменения копии сохранён
`config.before-qa-route.yaml`. Сам провайдер и его ключ не менялись.

Запрос через панель и движок к Dario завершился за 2,3 секунды с
`HTTP 401: OAuth access token has expired` и `finish_reason=error`.
Оболочка HTTP 200 не считается успешным ответом: `hermes.failed=true`,
расход токенов в ответе — нулевой. `/status` прокси при этом сообщал
`healthy`, `authenticated=true`, `expiresIn=0h 0m`; одного такого статуса
недостаточно для подтверждения работоспособности.

**Получение нового оформленного ответа от модели остаётся непроверенным
до восстановления провайдера.** После восстановления нужен один новый чат:
короткий вопрос и просьба о развёрнутом сравнении/плане, затем проверка ответа
без ручного указания Markdown. Подсказка подтверждена тестами, но выполнение
инструкции моделью этим не подменяется.

Вне репозитория создавались только свои временные данные, worktree, журналы
