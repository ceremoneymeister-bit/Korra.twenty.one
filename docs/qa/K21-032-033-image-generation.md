# K21-032 / K21-033 — GPT Image 2.5 native integration

## Provenance and scope

- Korra base: `b6412c07e7db8820bd736fc542ab5245c13c8670`
- Audited source: GPT Image 2.5 Agent Kit v0.3.1 at
  `cc52564687907194c8db02e95996757fb5d19b86`
- Integration shape: selective native port into `image_generate` and the
  bundled `openai-codex` provider. No external CLI or runtime is installed.

The provider exposes Sunburst and Flare, output controls, generation/edit
actions, ordered reference roles, masks, preservation guidance, prompt
presets, and optional sanitized receipts. Generated bytes are strict-base64
decoded, fully decoded with Pillow, checked against the requested format, and
atomically published without overwrite under the active profile.

## Runtime controls

`image_gen` is shipped in every image but remains absent from every platform's
implicit toolset. The profile owner must explicitly add it to each intended
`platform_toolsets.<platform>` list and select `image_gen.provider:
openai-codex`. One profile or platform's enablement does not enable another.

The provider obtains credentials only from Korra's active-profile Codex OAuth
broker. It does not read image-generation tokens from environment variables,
files, or commands. Each request makes one backend attempt, with no retry,
model fallback, or provider fallback. The Codex request continues to omit
`tool_choice` because that is the currently verified request shape.

## Validation and known limits

No live image request was made for this change. Local tests validate request
shape, strict terminal-result handling, image decoding and format checks,
atomic no-overwrite output, profile confinement, sanitized receipts, mask and
reference validation, exact model selection, one-attempt behavior, and
profile/platform opt-in isolation.

Backend acceptance remains account-dependent for Sunburst/Flare access,
custom sizes, masks, transparency, compression, and higher quality levels.
Unsupported source-kit features are the standalone CLI, arbitrary output
roots, overwrite mode, dry-run/review renderer, alternate token providers,
and named identity/style library commands. Korra supplies a profile-local
reference workflow in the bundled `gpt-image-2-5` skill instead.
