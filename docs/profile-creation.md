# Начальная память и материалы нового агента

Мастер `/profiles/new` предлагает необязательный раздел «Память и материалы».
Короткие факты идут в штатные MEMORY/USER, большой документ — в штатный
закреплённый материал. Новая беседа получает память при построении prompt;
документ доступен агенту через материалы/skills, а не целиком в каждом prompt.
Существующая беседа сохраняет свой снимок памяти.

Тот же результат доступен одним `POST /api/profiles`:

```json
{
  "name": "assistant",
  "display_name": "Помощник",
  "soul": "Помогай готовить документы магазина.",
  "idempotency_key": "create-assistant-001",
  "initial_knowledge": {
    "memory_char_limit": 6000,
    "user_char_limit": 4000,
    "memory": ["Самовывоз с 11 до 18."],
    "user": ["Обращайтесь ко мне на вы."],
    "material": {
      "title": "Условия доставки",
      "text": "Доставка по средам и пятницам."
    }
  }
}
```

`idempotency_key`: 16–128 латинских букв, цифр, `_` или `-`. Один ключ и
неизменные параметры возвращают тот же результат, в том числе после потери
ответа. Повтор не восстанавливает исходную память поверх правок владельца.
Другие параметры с тем же ключом, занятое имя или повтор после удаления
агента — 409. Для нового добавления нужен новый ключ.

`initial_knowledge` и отдельные лимиты необязательны; отсутствующие лимиты
сохраняют настройки нового/скопированного профиля. Явные лимиты — от 100 до
50 000 символов. До 64 записей и 50 000 символов на раздел; окончательная
вместимость и проверка текста — штатного MemoryStore. Отключённый раздел
не включается молча. Уменьшение лимита ниже уже скопированной памяти
отклоняется. Для копии `clone_all` начальные записи дополняют скопированные.
Исходный агент не меняется.

Один начальный `material` принимает `title`, необязательные `text`, `url`,
`filename`, `data_base64`. Для файла передайте имя и стандартный base64 без
префикса data URL. Предел исходного файла — 10 МиБ; форматы TXT, MD, CSV,
JSON, PDF, DOCX, XLSX. Текст/ссылка могут пояснять файл. Ссылка сохраняется,
сервер не скачивает её при создании. Действует существующая валидация материалов.

Роль, настройки и знания готовятся в закрытом staging-каталоге, затем агент
публикуется одним rename. Ошибка памяти/материала не оставляет наполовину
созданный профиль и не запускает его gateway. Имя операции сохраняется для
повтора после временной ошибки. Дополнительные материалы можно добавить
позже через `/api/profiles/{name}/materials`.

Готовый агент из каталога принимает тот же `initial_knowledge` с обязательными
`template_id`/`template_version`; настройки пакета остаются независимыми.
Legacy создание без ключа по-прежнему работает, но не принимает начальные
знания. Асинхронные `hub_skills` несовместимы с новым атомарным запросом:
их устанавливают после создания; старый путь без ключа сохранён.

## Общие навыки установки

Оператор может положить проверенные пакеты в `<корень DATA>/shared-skills/`:
каждый пакет содержит `SKILL.md` и свои ресурсы в отдельном каталоге. Папка
автоматически доступна главному, действующим и новым профилям этой установки,
включая готовых агентов из каталога. Копировать пакет в каждый профиль не нужно.
Профильный навык с тем же именем имеет приоритет; каталог из явного
`skills.external_dirs` также стоит выше общей папки. Профиль, созданный с
`--no-skills`, не получает общие навыки. Удаление пакета из общей папки убирает
его у всех профилей после обновления списка навыков; данные профилей не меняются.

Это возможность для навыков, которые владелец действительно хочет дать всем
агентам одного контура. Не помещайте сюда клиентские материалы другой установки,
секреты, записи разговоров или навыки, которые нужны только одной роли.
