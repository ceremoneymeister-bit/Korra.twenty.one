Навигация dashboard-плагинов Korra

Плагин работает внутри того же `BrowserRouter`, что и панель. Используйте
`window.__HERMES_PLUGIN_SDK__.router`, не включайте вторую копию `react-router`
в сборку плагина и не создавайте собственный роутер.

```js
const { React, router } = window.__HERMES_PLUGIN_SDK__;
const { Link, useNavigate, useHref, useSearchParams } = router;

function MyPanel() {
  const navigate = useNavigate();
  const address = useHref("/kanban?board=sales");
  // address подходит для копирования и уже содержит префикс кабинета.
  return React.createElement(Link, { to: "/kanban?board=sales" }, "Открыть доску");
}
```

В `to` и `navigate()` передаётся путь раздела **без префикса кабинета**.
`Link` строит настоящий `href` и меняет экран без перезагрузки; копирование
ссылки, открытие в новой вкладке и история браузера сохраняют обычное поведение.
`useNavigate()` нужен для перехода после действия, `useHref()` — для адреса
в буфере обмена, `useSearchParams()` — для выбранной доски или карточки в URL.
`NavLink` и `useLocation` доступны из того же объекта. Встроенные разделы
используют эти же компоненты из `react-router` напрямую.

Для внешних сайтов остаётся обычный `<a href="https://…">`. Для API,
загрузки файлов и WebSocket используются `SDK.fetchJSON`, `SDK.authedFetch`
и `SDK.buildWsUrl`: адрес API не является маршрутом страницы.

Как панель получает адрес:

1. nginx передаёт `/c/<клиент>/…` сервису кабинета. Его `app/proxy.py`
   снимает префикс с пути запроса и добавляет `X-Forwarded-Prefix`.
2. `korra_cli/web_server.py:mount_spa` нормализует заголовок, префиксует
   начальные ресурсы и внедряет `window.__HERMES_BASE_PATH__` в HTML.
3. `web/src/lib/api.ts` читает значение; `web/src/main.tsx` задаёт его
   как `basename` у единственного `BrowserRouter`.
4. `usePlugins` загружает ресурсы из `<префикс>/dashboard-plugins/…`;
   зарегистрированные компоненты и слоты рендерятся внутри роутера хоста.

Префикс не определяется по текущему пути, не задаётся отдельной переменной
каждому плагину и не вшивается в сборку. Без прокси он пустой.
Манифесты по-прежнему объявляют путь раздела, например `/kanban`.
Кэш манифестов разделён по базовому пути, чтобы кабинеты одного домена
не подхватывали маршруты друг друга.

Регистрация блока над расписаниями использует существующий слот:
`registerSlot("имя-плагина", "cron:top", Component)`.
В манифесте он декларируется как `"slots": ["cron:top"]`.

Контракт расширен без удаления прежних полей SDK. Обновлённым плагинам,
использующим `SDK.router`, нужен обновлённый основной фронт вместе с их файлами.
Проверка реальных плагинов и переходов: `web/src/plugins/navigation.test.tsx`.
