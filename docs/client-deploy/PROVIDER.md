# Провайдер модели на контуре клиента

Контур ходит к модели через прокси-провайдера. В конфиге он описывается как
именованный собственный провайдер и выбирается строкой `custom:<имя>`.
Флот-стандарт — имя `dario`.

**Адрес прокси и ключ у каждого контура свои.** Их выдаёт владелец под
конкретного клиента; чужой адрес или общий ключ на нескольких контурах — не
экономия, а один общий счёт и один общий отзыв доступа.

**Запасных провайдеров клиенту не ставим никогда.** Ни `fallback_model`, ни
второго провайдера «на случай перегрузки». Причина простая: подмена модели
происходит молча, и клиент получает другую модель, другой счёт и другие
условия хранения данных, ничего об этом не зная. Отказ провайдера должен быть
видимым отказом, который мы чиним, а не тихой подменой.

## Что где лежит

| Что | Где | Кто правит |
|---|---|---|
| Ключ | `.env` в каталоге данных, переменная `DARIO_API_KEY` | оператор при раскатке |
| Адрес и имя провайдера | `config.yaml`, секция `custom_providers` | оператор при раскатке |
| Выбор модели | `config.yaml`, `model.provider` и `model.default` | оператор, дальше клиент из панели |

Ключ в `config.yaml` **не пишем**. В конфиге стоит только имя переменной
(`key_env`), а значение живёт в `.env` с правами 600. Так конфиг можно
показать, переслать и положить в архив разбора, не раздав при этом доступ.

## Секция в config.yaml

Файл `config.yaml` появляется в каталоге данных при первом запуске. Дописать
в него (или поправить, если секция уже есть):

```yaml
model:
  default: claude-opus-4-8
  provider: custom:dario

custom_providers:
  - name: dario
    base_url: https://<адрес-прокси-этого-контура>
    key_env: DARIO_API_KEY
    api_mode: anthropic_messages
    model: claude-opus-4-8
    models:
      claude-opus-4-8: {}
      claude-opus-4-8[1m]:
        context_length: 1000000
      claude-sonnet-5: {}
```

Разбор по строкам:

- `name` — имя провайдера. Именно оно подставляется в `model.provider` как
  `custom:dario`.
- `base_url` — адрес прокси этого контура.
- `key_env` — **имя переменной** из `.env`, а не сам ключ.
- `api_mode` — формат запросов. Для прокси к моделям Anthropic это
  `anthropic_messages`; без него формат угадывается по адресу и может
  определиться неверно.
- `model` — модель по умолчанию у самого провайдера.
- `models` — какие модели показывать в выборе. Записи с `[1m]` — расширенное
  окно контекста, `context_length` для них указывается явно.

Правка через `korra config set` годится для простых значений:

```bash
docker exec -u 10000 korra sh -c 'korra config set model.provider custom:dario'
docker exec -u 10000 korra sh -c 'korra config set model.default claude-opus-4-8'
```

Список `custom_providers` проще дописать редактором. Перед правкой — копия:

```bash
cp /opt/korra/data/config.yaml /opt/korra/data/config.yaml.bak-$(date +%Y%m%d)
```

После правки:

```bash
chown 10000:10000 /opt/korra/data/config.yaml
docker restart korra
```

Ключ в `.env` подхватывается и без перезапуска: движок перечитывает файл и
пересобирает клиента, когда значение изменилось. Изменение `base_url` в
конфиге требует перезапуска.

Отступы в YAML значимы. Записи списка начинаются с `- `; если сделать
`custom_providers` словарём вместо списка, движок это заметит и напишет об
этом в журнале, но провайдер работать не будет.

## Профили: у каждого свой конфиг и свой .env

Профиль (отдельный агент во вкладке панели) — это отдельный каталог
`profiles/<имя>/` со **своим** `config.yaml` и **своим** `.env`. Наследования
от главного конфига нет: провайдер, описанный только в главном файле, для
профиля не существует.

Профили, созданные конструктором в панели, получают копию секции провайдера в
новом формате — он равноправен:

```yaml
providers:
  dario:
    name: dario
    api: https://<адрес-прокси-этого-контура>
    key_env: DARIO_API_KEY
    api_mode: anthropic_messages
    models:
      claude-sonnet-5: {}
```

(`api`, `url` и `base_url` здесь синонимы; `enabled: false` временно
выключает запись, не удаляя её.)

Отсюда самый частый симптом: **новый агент молчит**. В девяти случаях из
десяти это не поломка, а отсутствие провайдера или ключа в конфиге профиля.

## Проверка

```bash
docker exec -u 10000 korra sh -c 'korra config get model'
docker exec -u 10000 korra sh -c 'korra doctor' | tail -20
```

Живая проверка одна: написать в чат панели и получить ответ. Команды выше
показывают, что конфиг разобран, но не что прокси отвечает и ключ принят.

## Если агент молчит

По порядку, сверху вниз:

1. Ключ на месте и не пустой: `grep -c '^DARIO_API_KEY=..' /opt/korra/data/.env`
   должен вернуть 1.
2. Имя переменной в `.env` буква в букву совпадает с `key_env` в конфиге.
3. `model.provider` — это `custom:dario`, а не `dario` и не `auto`.
4. Модель из `model.default` перечислена в `models` у провайдера.
5. Если молчит только один агент — смотрите `profiles/<имя>/config.yaml` и
   `profiles/<имя>/.env`, а не главные файлы.
6. Журнал: `docker logs --tail 50 korra` и `/opt/korra/data/logs/`.

Ключи можно посмотреть и из панели: раздел **«Ключи»** (адрес `/env`).
Значения там скрыты, видно только, что переменная задана.

## Смена ключа

```bash
nano /opt/korra/data/.env          # заменить значение DARIO_API_KEY
```

Перезапуск не нужен: новое значение подхватится на следующем ходу разговора.
Если ключ менялся из-за утечки, отдельно проверьте, не осталось ли старого
значения в конфигах профилей и в архивах бэкапа.
