# Korra · визуальный дашборд v1

21.09.2026. Интерактивный макет для визуальной приёмки Дмитрием. Название
«Артефакты» и визуальная основа v1 приняты владельцем: «шикарно прям»,
«уже нравится — берем». Затем Дмитрий предложил ориентироваться на продуманность
виджетов iOS, в частности на изменение размера. После замечания о разной
высоте одинаковых S Дмитрий согласовал единый стандарт геометрии: S 1×1,
M 2×1, L 2×2. Стандарт реализован; оценка обновлённой композиции ещё впереди.

## Граница

Это настоящая оболочка React App, каталог и границы ошибок из каркаса
`189af61017`, с **preview-only** заменой маршрута через `vite.dashboard.config.ts`.
Продуктовый entry point этот код не импортирует. Изменение в продуктовых
исходниках — только название карточки «Артефакты»; её ID `recent-results`
сохранён для совместимости раскладок.

Все числа, имена агентов, поручения, артефакты и письмо — демонстрационные.
Транспорт берётся из существующего `prototypes/interface/demo-api.ts`:
неизвестные запросы не пересылаются в сеть. Дополнительно HTML запрещает
сетевые подключения и отправку форм через CSP. Реальная авторизация,
данные кабинета, модели, отправка писем и расписания не подключены.

## Что можно проверить

- Три состояния в нижнем переключателе: первый вход, рабочий день, нужно решение.
- Артефакты открываются в просмотре, текст образца скачивается как `.md`.
  Формат скачивания назван явно: это не настоящий PDF/XLSX из карточки.
- «Все» показывает и третий артефакт, скрытый из краткого мобильного блока.
- Переключение периода показателя, детали агентов и событий.
- Письмо можно изучить и подтвердить **в макете**, без внешней отправки.
- В настройке — включение и порядок карточек. Только локальное,
  namespaced-хранилище `korra.dashboard.visual-v1.layout`; не продуктовый
  серверный контракт, не синхронизация и не хранение личных данных.
- Стандартные светлая/тёмная темы оболочки, клавиатура, reduced motion.
- S/M/L у «Артефактов», показателя, агентов и ленты дня. Переключатели доступны
  в «Настроить», стрелки клавиатуры работают как в стандартной radio-group.
  Размер, порядок и скрытие сохраняются независимо. Старый формат настроек
  мигрирует без сброса. Выбор буквы остаётся прежним, но габариты теперь
  едины для всех типов карточек, включая M.

## Единая модульная сетка

Размер определяется только буквой, не содержимым: **S 1×1, M 2×1, L 2×2**.
Модуль квадратный, промежуток входит в размер составной плитки. При ширине
полотна более 880 px — 4 колонки, иначе 2. Ширина полотна, а не окна,
учитывает боковую навигацию. Промежуток: 24 px / 20 px, на полотне до 440 px — 16 px.
Высота строк вычисляется из ширины общего модуля; у виджетов нет индивидуальной
высоты. Например, на широком полотне: S 262×262, M 548×262, L 548×548.

Материалы, палитра и обложки принятой v1 сохранены; прежняя асимметрия
M по типу карточки сознательно заменена согласованной геометрией.
Содержимое адаптируется внутри плитки, без внутренней прокрутки.

| Виджет | S | M | L |
|---|---|---|---|
| Артефакты | Одна свежая обложка и переход ко всем | Три превью, два на телефоне | Главное превью и два дополнительных, авторы |
| Показатель | Крупное краткое число с единицей и изменением | Число и график | Более крупный график и значения для сравнения периодов |
| Агенты | Число работающих и единый переход к команде | Список; на телефоне три аватара с именами | Агенты с текущим шагом |
| Лента дня | Ближайшее событие и переход ко всем | Три события | Неделя и лента событий |

S на телефоне занимает полстроки. «Внимание» вынесено из плиточной сетки
в отдельную полосу над ней, его нельзя переставлять среди плиток. При
перестановке карточек старое положение attention в хранилище пропускается.
Визуальный порядок совпадает с DOM/клавиатурным; плотное CSS-backfill не
переставляет карточки, поэтому некоторые смешанные порядки оставляют свободные ячейки.

Источник вдохновения — [Apple, Principles of great widgets](https://developer.apple.com/videos/play/wwdc2021/10048/):
размеры, варианты содержимого и конфигурация служат персонализации. В Korra
сохраняются собственная палитра, типографика, рельеф и семантика действий.

Состояние «Внимание» появляется только в сценарии, где действительно задан
демонстрационный вопрос. При загрузке отсутствующие реальные данные не
подменяются этими fixtures: макет собирается отдельной командой.

## Запуск и проверка

Из `engine/web`, с зависимостями соответствующего checkout:

```sh
../node_modules/.bin/vite --config vite.dashboard.config.ts
../node_modules/.bin/tsc -p tsconfig.dashboard.json --pretty false
../node_modules/.bin/vitest run src/lib/dashboard-preview.test.ts src/lib/dashboard-layout.test.ts src/components/dashboard/DashboardWidgetBoundary.test.tsx
../node_modules/.bin/eslint prototypes/dashboard/*.ts prototypes/dashboard/*.tsx src/lib/dashboard-preview.test.ts src/components/dashboard/widgets/RecentResultsWidget.tsx vite.dashboard.config.ts --max-warnings 0
../node_modules/.bin/vite build --config vite.dashboard.config.ts
```

Vite слушает только `127.0.0.1:5186`. Build попадает в `dist/` рядом с этим
engine worktree, **не** в продуктовый `korra_cli/web_dist`.

Для браузерной проверки собранной версии:

```sh
# Из engine; сервер только для статических файлов.
PYTHONDONTWRITEBYTECODE=1 python3 -m http.server 5187 --bind 127.0.0.1 --directory ../dist
node web/prototypes/dashboard/check.cjs
node web/prototypes/dashboard/check-sizes.cjs
```

`KORRA_DEMO_URL`, `KORRA_DEMO_EVIDENCE`, `KORRA_PLAYWRIGHT`, `KORRA_CHROMIUM`
переопределяют адрес и локальные инструменты теста. Browser harness проверяет
три сценария на 320, 390, 768, 1024, 1440, 1920 px; клавиатурный цикл и возврат
фокуса, сохранение после перехода и reload, скачивание, подтверждение, темы,
reduced motion, восстановление пустого набора и отсутствие сетевых API-запросов.
`check-sizes.cjs` проверяет реальные габариты каждого виджета по формуле
модуль×число + промежутки (не скриншотные константы): 36 сочетаний S/M/L
на 320, 360, 390, 600, 768, 1024, 1100, 1160, 1180, 1280, 1440, 1920 px. Дополнительно:
смешанная раскладка, тёмная тема, полоса внимания вне сетки, вертикальное и
горизонтальное переполнение карточек, клавиатура, сохранение и миграция.
До исправления новая геометрическая проверка воспроизвела дефект на S.

Дмитрий отдельно разрешил публичную демо-ссылку. `bash publish.sh` публикует
только статическую сборку в `/var/www/sites/korra21-dashboard-v1`; чужие каталоги,
страницы входа и кабинет не меняет. Скрипт отказывается перезаписывать каталог
без собственного маркера и не удаляет старые хешированные assets.
